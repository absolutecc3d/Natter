Make your own Natter server

A complete guide to setting up your own Natter server with Firebase.

1. What you need

To make a Natter server, you need:

  • A Google account
  • A Firebase project
  • Firestore
  • Firebase Anonymous Authentication
  • The Natter HTML file
Natter uses Firebase as the backend. Your messages, presence information, server settings and ownership information are stored in your Firebase project.

2. Create a Firebase project

  1. Go to the Firebase Console.
  2. Click Create a project.
  3. Give your project a name.
  4. Finish creating the project.

You can name the Firebase project whatever you want. It does not have to be called Natter.

3. Add a Web App

  1. Open your Firebase project.
  2. Open Project settings.
  3. Find Your apps.
  4. Click the Web icon.
  5. Give your app a name.
  6. Register the app.

Firebase will then show you a configuration object similar to this: 

{
  "apiKey": "AIza...",
  "authDomain": "your-project.firebaseapp.com",
  "projectId": "your-project",
  "storageBucket": "your-project.firebasestorage.app",
  "messagingSenderId": "123456789",
  "appId": "1:123456789:web:abcdef"
}
Keep this configuration available. You will put it into the Natter connection screen.

4. Enable Anonymous Authentication

Natter uses anonymous Firebase accounts to identify users.

  1. Open Authentication in Firebase.
  2. Open the Sign-in method tab.
  3. Find Anonymous.
  4. Enable it.
  5. Save.
If Anonymous Authentication is disabled, people won't be able to join your Natter server.

5. Create Firestore

  1. Open Firestore Database.
  2. Click Create database.
  3. Choose the appropriate location.
  4. Finish creating the database.

After creating it, open the Rules tab.

6. Add the Natter rules

Replace the Firestore rules with these: 

rules_version = '2';

service cloud.firestore {
  match /databases/{database}/documents {

    match /messages/{message} {
      allow read, create: if request.auth != null;
    }

    match /presence/{presenceId} {
      allow read, create, update, delete:
        if request.auth != null;
    }

    match /server/claim {
      allow read: if request.auth != null;

      allow create: if request.auth != null;

      allow update: if request.auth != null
        && resource.data.ownerId == null
        && request.resource.data.ownerId == request.auth.uid;

      allow delete: if request.auth != null
        && resource.data.ownerId == request.auth.uid;
    }

    match /server/settings {
      allow read: if request.auth != null;
      allow create, update: if request.auth != null;

      allow delete: if request.auth != null
        && resource.data.ownerId == request.auth.uid;
    }

  }
}

Then click Publish.

Make sure you actually publish the rules. Having the rules written in the editor without publishing them does not change the active rules.

7. Get your Firebase config

Go back to:

Firebase → Project settings → Your apps → Web app

Find the Firebase SDK configuration and copy the configuration object.

It should contain things such as:

  • apiKey
  • authDomain
  • projectId
  • storageBucket
  • messagingSenderId
  • appId
The Firebase Web App configuration is intended to be used by your web application. Do not confuse it with private Firebase service-account credentials or Admin SDK keys.

8. Connect Natter

Open your Natter page.

Paste your Firebase configuration into the Firebase configuration box and connect.

Natter will then:

  • Connect to your Firebase project
  • Sign you in anonymously
  • Load the server
  • Load the messages
  • Load the online users
  • Load the server settings

9. Claim your server

The first person who owns a server can claim it.

Step 1 — Open the claim window

Click the Claim button in Natter.

Natter will generate a random verification code.

Step 2 — Open Firestore

Go to:

Firestore Database → Data

Create this collection and document: 

server
└── claim

Step 3 — Add the code

Inside server/claim, create: 

code = "THE_CODE_NATTER_GAVE_YOU"

Natter will detect the document and verify the code.

Step 4 — Ownership is saved

After verification, Natter stores your Firebase UID as: 

ownerId = "your-firebase-user-uid"

That UID identifies you as the server owner.

Your browser also remembers that you have claimed the server, so you don't have to perform the claim process every time you reload Natter.

10. Set the server name

The server name is controlled directly through Firestore.

Open:

Firestore Database → Data → server → settings

Create the settings document if it doesn't exist. Then add: 

serverName = "gaming"

Natter will display: 

#gaming

For example, if you change it to: 

serverName = "friends"

Natter will show: 

#friends
You don't change the server name inside the Natter chat itself. It is controlled from the server/settings Firestore document.

11. How ownership works

The owner is identified by the Firebase UID stored in: 

server/claim → ownerId

When the owner sends a message, Natter stores an additional field: 

owner: true

This lets Natter display the owner badge on the owner's messages.

A normal user's message has: 

owner: false

So the message data can look roughly like: 

{
  "text": "hello!",
  "name": "yxn",
  "uid": "abc123...",
  "owner": true,
  "createdAt": "..."
}

12. Firestore structure

Once your server is running, your database will look roughly like this: 

server
├── claim
│   ├── code
│   └── ownerId
│
└── settings
    └── serverName

messages
├── random-message-id
├── random-message-id
└── ...

presence
├── random-presence-id
├── random-presence-id
└── ...

server/claim

Contains information about who owns the server.

server/settings

Contains settings such as the server name.

messages

Contains the chat messages.

presence

Contains temporary information about users who are currently online.

13. Clear all messages

Want to completely wipe the chat history and start fresh? You can do it directly from Firestore.

  1. Open Firestore Database → Data.
  2. Find the messages collection.
  3. Delete the entire messages collection.

You do not need to create the collection again manually. When someone sends a new message, Natter automatically creates the messages collection again and adds the new message. 

messages
→ DELETE COLLECTION
This permanently clears the messages currently stored in that collection. Make sure you actually want to remove the chat history before deleting it.
Once the first new message is sent, Firestore automatically creates messages again.

14. Troubleshooting

Anonymous authentication error

Make sure Anonymous Authentication is enabled:

Authentication → Sign-in method → Anonymous → Enable

Permission denied

Check that your Firestore Rules are exactly the Natter rules from this guide and that you clicked Publish.

The server name isn't changing

Check that the document is exactly: 

server/settings

and the field is exactly: 

serverName

Claiming doesn't work

Check that the document is: 

server/claim

and that the field is: 

code

The code must exactly match the code displayed by Natter.

Messages aren't appearing

Check your Firestore Rules and make sure the user is successfully signed in anonymously.

Done!

That's it. You now have your own Natter server. 🎉

Give people your Natter page and your Firebase configuration, and they can connect to your server.

Remember: your Firestore Security Rules are extremely important. They determine what users connected to your server are allowed to do.
